# Translating STS2 mods

> Generated by Sts2ModTranslator on every launch. Edits to this file are overwritten.

This folder is the working directory of **Sts2ModTranslator**. The mod scans every
installed STS2 mod, dumps its original text here, and injects whatever you write
back into the live game — no rebuild needed.

Everything below is relative to this folder. You do not need any path from the user.

## Layout

```
supported_mods.txt        # report: which mods, which tables, coverage. START HERE.
glossary_<lang>.txt       # official in-game term for each keyword, in <lang>
glossary/<mod>/<lang>.txt # OPTIONAL: user's term list for this mod (names, mechanics)
source/<mod>/<lang>/<table>.txt      # original text — READ ONLY, never edit
overrides/<mod>/<lang>/<table>.txt   # your translation — edit these
```

Files are `.txt` but the content is **JSON**: a flat `{"loc_key": "text"}` map.
(The `.txt` extension keeps the game's mod loader from parsing them as manifests.)

## The two rules that matter most

**1. An empty value means "not translated yet".** The game falls back to the
original text for that key. So:
- Never delete a key. Never add a key. The key set must stay byte-identical to `source/`.
- Leave a value `""` only if you genuinely can't translate it.
- Only fill in blanks unless told otherwise — never overwrite existing translations.

**2. `source/` holds *every* language the mod ships, not just English.**
Check `ships_langs` in `supported_mods.txt`. Read the mod's real source language —
some mods ship Chinese or Korean text inside the `eng/` folder. Other shipped
languages are useful cross-references when the English is ambiguous.

## Placeholder syntax — what to keep, what to translate

This is where machine translation fails and you win. Read this section carefully.

| Form | Real example | What to do |
|---|---|---|
| `{Name}` | `Reduce damage taken by {Amount}%.` | keep verbatim |
| `{Name:func()}` | `deal {Damage:diff()} damage` | keep verbatim |
| `{}` | `[blue]{}[/blue] cards` | keep verbatim (= the value itself) |
| `[tag]…[/tag]` | `Remove 1 random [blue]Common[/blue] card` | keep tags, translate the text between them |
| `[img]…[/img]` | `[img]res://images/silk_icon_text.png[/img]` | **never translate the `res://` path** |
| `[color=#hex]` | `[sine][color=#D62000]…[/color][/sine]` | keep the attribute exactly |
| `!Var!` | `deal !D! damage`, `(minimum !ChargeCost!)` | keep verbatim (BaseLib value token) |
| `*keyword` | `gain !Strength! *Strength` | keep the `*`; translate the word after it |
| `/+` `/-` | `*Anti/-Purge`, `(/+2, elite /+3)` | keep verbatim — BaseLib escapes, `/-` is a hyphen *inside* a keyword |
| leading `#` | `#Retain. Exhaust. NP: …` | keep it as the first character |

### ⚠ The plural/cond trap — the #1 real bug

`{Name:plural:…}` and `{Name:cond:…}` **contain translatable text inside them.**
Machine translation masks the whole `{…}` and leaves the branches in English.
Do not repeat that mistake.

```
source:  Choose {Amount:plural:a card|[blue]{}[/blue] cards}.
BAD:     {Amount:plural:a card|[blue]{}[/blue] cards}를 선택하세요.   ← branches left in English
GOOD:    {Amount:plural:카드 한 장|[blue]{}[/blue]장의 카드}를 선택하세요.
```

Rules for these:
- Translate the literal text **inside each branch**.
- Keep the **exact same delimiter**. It varies between entries — both
  `{Amount:plural:a|b}` and `{Amount:plural:a:b}` occur. Copy whatever the source uses.
- Keep the condition part untouched: in `{Repeat:cond:>0?…|…}`, `>0?` is structure.
- An empty branch is meaningful: `{Upgrade: and [gold]Upgrade[/gold]|}` — the trailing
  `|}` is an empty "else". Keep it.
- Nested placeholders inside a branch (`[blue]{}[/blue]`) stay verbatim.

### Branch count depends on the target language — do not copy the source's count

The game picks a branch using SmartFormat's plural rule **for the target language's
culture**. Getting the count wrong renders the wrong branch, silently.

**For `kor`, `jpn`, `zhs`, `zht`, `tha`: use exactly ONE branch.**

These languages resolve to SmartFormat's `Singular` rule, which is literally
`(value, count) => 0` — it always picks branch 0 no matter how many you write and no
matter what the number is. Two branches means the "singular" text renders even when
the value is 5. No error is raised; the sentence is just wrong.

```
source:  Choose {Amount:plural:a card|[blue]{}[/blue] cards}.
BAD:     {Amount:plural:카드 한 장|[blue]{}[/blue]장의 카드}를 선택하세요.
             → renders "카드 한 장" even when Amount is 3
GOOD:    {Amount:plural:[blue]{}[/blue]장의 카드}를 선택하세요.
```

The vanilla game confirms this: it uses `:plural:` over 3000 times across English,
German, French, Spanish, Italian, Polish, Portuguese and Turkish — and **zero times**
in Korean, Japanese, Chinese or Thai. Writing the number inline without the `plural:`
formatter at all (`[blue]{Amount}[/blue]장의 카드`) is also correct and is what vanilla
does; keep `plural:` with one branch if you prefer a smaller diff.

**For other languages**, match the target language's grammar, which may differ from the
source's count. Vanilla Polish uses three branches where English uses two:
`{Cards:plural:kartę|karty|kart}` vs `{Cards:plural:card|cards}`.

## Keyword consistency

**Vanilla terms** — `glossary_<lang>.txt` maps each STS2 keyword to the game's own
official term in that language, extracted from the game itself. Use it. If the
glossary says `Vulnerable` → `취약`, never write `취약성` or `연약함`.

If there is no `glossary_` file for your target language, none shipped for it — fall
back to the keyword wording the game itself uses, and above all stay self-consistent.

**Mod-specific terms** — if `glossary/<modId>/<lang>.txt` exists, it is the user's own
term list for this mod (character names, unique mechanics): `{ "original": "translation" }`.
Treat it as binding — whenever an entry's original contains one of these terms, its
translation must use the mapped wording exactly. (The in-game editor flags entries that
don't with a "term" marker.) The user maintains it, so honour it over your own guess.

**Mod-defined keywords** — the game glossary does not cover these, and they cross mod
boundaries. BaseLib defines `PURGE`; ArtoriaCaster references it as `*Anti/-Purge`.
If BaseLib's title says one thing and ArtoriaCaster's card text says another, the
in-game keyword tooltip silently stops matching.

So: before translating a mod that depends on another (check `dependencies` in the
target's manifest, and BaseLib in particular), read the dependency's **already
translated** `overrides/<dep>/<lang>/card_keywords.txt` and `powers.txt`, and reuse
its exact wording. Pick one term per concept and keep it across every file and mod.

## Workflow

1. Read `supported_mods.txt`. It lists each mod's `id`, `tables`, `keys_total`,
   `keys_translated`, `coverage`, and an absolute `edit_folder`.
   **Its `target_lang` reflects the language the game was last launched in** — if the
   user wants a different language, work in `overrides/<mod>/<lang>/` directly and
   ignore the coverage numbers in the report, they are for another language.
2. Confirm the target mod + language with the user if ambiguous.
3. Work **one table file at a time**. Some are large (`HextechRunes/relics.txt` has
   2430 keys) — do not try to hold everything at once. Read the `source/` file and the
   matching `overrides/` file, fill the blanks, write it back.
4. Preserve JSON shape: UTF-8, no escaping of CJK, keys sorted, indented.
5. Verify (below), then tell the user to press **Reload** in the in-game panel.

## Verify before you finish

For every entry you changed, compare against the same key in `source/`:

- The multiset of `!Var!` tokens, `[tag]`/`[/tag]` pairs, and leading `#` must be
  **identical**. Only the human-readable text differs.
- Every `{Name}` / `{Name:func()}` that carries a value in the source must still be
  present. `[img]` paths unchanged.
- `plural:` branch counts follow the **target language**, not the source — see above.
  For kor/jpn/zhs/zht/tha, assert there is exactly one branch (no `|` or `:` splitting
  the branch text).
- The file must still parse as JSON.

Broken entries do **not** crash the game — they are silently dropped at injection
time, so the user just sees untranslated English and won't know why. That silence is
exactly why you check.

The authority is the in-game panel: the Files view shows `⚠ N bad {format}` per table.
`N` must be 0. If you can't see the panel, ask the user to check it.

## Don't

- Don't edit anything under `source/` — it is rewritten every boot; your edits vanish.
- Don't create `.json` files here. The game's mod loader parses every `.json` under
  `mods/` as a manifest and logs "missing id" for each one. Data goes in `.txt`.
- Don't touch `deepl_key.txt`, `author.txt`, `pack_*.txt` — panel state, not translation.
- Don't translate a mod into its own source language (a zhs mod into zhs).
